# Security policy

## Supported releases

Only the latest 1.x result release receives security corrections. Historical result bundles remain immutable; a correction is published as a new release and recorded in [CHANGELOG.md](CHANGELOG.md).

## Report a vulnerability

After publication, use the repository's **Security** tab and **Report a vulnerability**. Private vulnerability reporting must be enabled before the first public release. Do not post real credentials, corpus rows, prediction output, logs, internal endpoints or private token formats in an issue or pull request.

Include the affected release, detector or script version, reproduction steps using synthetic data, and non-sensitive hashes. If private reporting is unavailable, do not disclose the sensitive material publicly; ask the maintainer to enable the private channel without including the material.

This local publication candidate has no remote and cannot yet receive reports.
